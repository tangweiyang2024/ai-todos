# Agent 会话看板调研

## 基于当前 ai-todos 工作区的建议

1. **先处理需要我关注的事**：将等待输入、等待审批、执行失败和已停止待确认分开展示，运行中靠后；同组按最近活动时间排序，允许按项目过滤。
2. **会话卡片回答三个问题**：做什么（现有标题与原始 preview 的简短片段）、现在怎样（状态与观察时间）、接下来做什么（打开原会话或人工确认）。当前 preview 是宿主返回的文本，不应当标为 AI 摘要；真正生成摘要要单独设计更新时机、成本和隐私。
3. **状态可信度可见**：显示 hook/宿主/历史来源和最近观察时间；“超时未见活动”只提示状态未知，不等同卡住。手工确认完成仅记录人工动作；新一轮执行后需要重新确认。
4. **会话历史以重要变化为主**：记录开始、等待、停止、失败、人工确认和继续执行；支持从某个会话看它自己的历史。旧记录缺失时明确提示，不从最后状态倒推。
5. **保持轻量**：沿用 Codex 的会话与审查入口；项目仅作为分组或筛选，优先验证信息和跳转是否解决问题，再考虑通知、批量操作或差异预览。

当前工作区 `src/codex.ts` 将宿主 preview 截断后保存，并从 hook、宿主或 rollout 推导状态；`src/domain.ts` 对超过五分钟未更新的活跃状态投影为未知。上面的排序、来源展示和卡片策略属于建议，并非声称已经实现或已部署。工作区存在尚未部署的本轮界面修改，线上实际表现需单独核实。
