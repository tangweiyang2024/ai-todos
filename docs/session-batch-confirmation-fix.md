# 批量确认弹窗与旧连接归档兼容修复

## 已验证原因

2026-11-18 17:18:11 和 17:18:13（Asia/Shanghai），本机桌面日志明确记录：

```text
MCP error -32602: Invalid arguments for tool ai_todos_confirm_session:
Unrecognized key: "archive"
```

已打开的 MCP 连接仍使用旧工具参数定义，新增 archive 字段在请求到达本地归档逻辑之前被拒绝。弹窗和 confirmSession 的 silent 分支丢失错误细节，只显示汇总数量。

在个人数据库的隔离副本中验证：普通确认拒绝 interrupted，显式 archive 能成功；真实个人记录未被修改。

## 修复

- 嵌入式归档使用现有稳定 UI 信封，动作 archive_session 的 confirmation 由本地服务严格校验；必须显式 archive=true，仍检查显示版本，不接受关联业务任务。
- 普通确认保留原入口。归档成功与后续刷新分开处理，刷新失败不能伪报归档失败。
- 独立弹窗样式包含选择概览、横向状态筛选、项目短名、状态标签和固定操作区；逐行显示实际错误，保留部分成功结果。
- 刷新只更换展示版本，重新确认必须由用户再次点击；仅累计本弹窗成功项，避免重试少报或计入他人的完成项。

## 验证

- 类型检查、插件构建、133 项全量回归、打包 MCP 归档测试通过。
- 模拟旧 MCP 顶层 archive 拒绝规则，使用真实 MCP、服务和隔离 SQLite 进行浏览器验证。
- 两项初次确认一成功、一版本冲突；逐行显示“会话已变化，请刷新并重新确认”。刷新不增加归档请求数，用户重试后累计提示“已完成 2 个会话”。
- 归档共走 3 次稳定 UI 动作（含一次被版本校验拒绝的请求）；旧确认工具调用 0 次。
- 关联任务验收状态、过期版本拒绝和显式人工确认边界均保留。浏览器测试未确认任何真实用户会话。
- 本机插件和服务已备份替换，wikiUiRevision=8。HTTP 页面与安装包一致，SQLite integrity_check=ok；4 条旧候选、7 个沉淀聊天关联及报障会话的未确认状态均保持不变。
