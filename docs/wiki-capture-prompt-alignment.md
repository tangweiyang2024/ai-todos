# 沉淀提示词与本机 ingest 规范对齐

2026-11-19。沿用既定流程：原生首轮只读提取 → 人工筛选 → 查重/冲突及拟写内容 → 明确批准后完整 ingest。此次只修正提示词准确性，不写正式 Wiki。

- 明确 Vault、LLM Wiki 项目根、wiki 内容目录三个路径；启动和正式写入前读取各层存在的 AGENTS.md/CLAUDE.md、本机 llm-wiki-ingest、通用 ingest Skill；批量代理文档不替代主流程。
- 提取标准使用可复用业务/技术结论、具体适用范围与机制、原文结果证据、事实分级和未验证事项；删掉流水、泛泛建议和已被推翻的结论。用户确认候选后才进行正式 Wiki 查重与写入方案。
- 本机规范覆盖通用默认值：raw/ 来源、wiki/chats/code/ 会话页、log 末尾追加、按需人读文档。manifest 读取现存位置，不因 raw 命名差异新建平行清单；路由结果按本机约束校验。
- 完整 ingest 方案覆盖来源快照、来源摘要/相关主题页、来源与双链、索引/hot/log/已用manifest，含每个文件的基线、修改和原因。批准后按正确知识库根的 transport/mode/锁执行，按实际改动验证。
- 首轮只读不运行会写配置的detect/lock/allocator，不要求模型写进度；后续按允许权限回报。
- 先用现有入口重新打开并核查资源，定位用户设置页缺少模型卡片的版本差异，不改用户默认模型。

验证：提示词契约回归、完整来源不变与审批边界、UI真实资源检查、类型检查、全量回归与打包集成。已有会话说明保持不可变，新提示词用于新创建任务；不静默重发或替换已审核内容。

## 发现的具体差异

1. 原提示词没有准确列出知识库项目根的 CLAUDE.md，未列出 AGENTS.md、本机适配 Skill；已区分 Vault 根、知识库项目根和 Wiki 内容层。
2. 通用 ingest 的 `.raw/`、`wiki/sessions/`、日志头插与本机约定不同；来源使用 raw/，会话页使用 wiki/chats/code/，log 末尾追加，同时复用实际存在的 `.raw/.manifest.json` 而不创建平行清单。
3. 批量 `agents/wiki-ingest.md` 不更新总索引/日志/热缓存，是因为这些由主代理完成；单源沉淀仍须完整执行。
4. 首轮仅接受有可复用机制及原文结果依据的候选；模型自称“已验证”不是工具结果，后续纠正覆盖旧假设。
5. 索引/hot/log/manifest、持久配置及启用地址分配器时的计数器副作用纳入方案；人读文档按真实目标范围保护，不将根外路径交给知识库相对路径锁脚本。可替代 transport 降级，锁必须保持等价约束。
