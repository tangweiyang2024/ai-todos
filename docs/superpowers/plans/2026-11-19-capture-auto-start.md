# 沉淀默认模型与原生后台提取实施计划

> 执行方式：在本会话按 test-driven-development 与 verification-before-completion 逐项实现和验证。用户已授权自动开发，并选择可配置默认模型。

**目标：** 点击沉淀后后台提取，首次结果可直接审核，无需进入会话再发送提示词。

**架构：** 复用持久准备任务、源快照及普通 Codex 会话。设置保存独立的默认模型/推理强度，每次任务固定配置。使用原生 `codex exec resume --json` 提交首轮，保留原生历史和上下文管理；ai-todos 仅接收生命周期。首轮只读，关闭外部 MCP/apps/plugins，禁止正式知识写入。后续审核和 ingest 在原生会话执行。

**兼容：** 已开始会话只打开、不追加。旧版仅准备会话可显式触发一次后台首轮。模型目录失效明确失败；无默认模型先引导设置。派发前落盘，服务中断或执行结果不确定时不得自动重发；可进入原会话核对。完成提醒只在首轮真实完成后发出。

- [x] 默认模型：稳定 Wiki UI 信封读取/保存设置；校验账户目录与版本；UI 独立设置卡片。
- [x] 原生执行：独立 CLI 适配器，限制首轮权限，校验线程事件、完成结果、取消/期限和错误；持久化派发状态防重复。
- [x] 编排：准备→提取→待审核；固定模型；旧会话兼容；重启保持诚实状态。
- [x] 验证：先运行失败测试，再实现；覆盖配置持久、去重、失败、重启、Wiki 未写入。运行全量回归、typecheck、构建、浏览器隔离验证。
- [x] 安装：备份已安装插件与数据，原位替换构建产物、重启服务并检查版本/哈希；不改真实会话确认状态，不推送远端。


## 验证记录

- 真实原生 CLI：空 thread/start 还未持久化 rollout，inject_items 后可 exec resume；保留交接注入流程。
- 真实生产函数：隔离源使用 gpt-6.2-sol / low 跑通；turn_context 验证实际 low 与 read-only。结果列出带 turn/item 证据的一条候选，明确尚未验证代码和测试，等待人工审核，测试 Wiki 内容未变。
- 浏览器：无默认模型引导设置，保存后刷新保留；提取运行时无完成弹窗；真实结束后弹窗；刷新保留提醒；查看结果仅打开同一 threadId，无 prompt 参数。执行计数 1，测试 Wiki 未变。
- 审查：修复重启误报已提取、已有轮次跳过误报完成、MCP覆盖参数被CLI错误解析；当前审查无剩余确定问题。
