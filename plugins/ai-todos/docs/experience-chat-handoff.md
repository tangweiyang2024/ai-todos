# 经验沉淀：移交普通 Codex 会话

2026-11-16，按用户进一步简化的方案实现。

## 当前交互

1. 在原会话或关联任务卡片点击“沉淀经验”，接口立即接受后台任务，卡片显示准备阶段；其他操作保持可用。
2. 后台核对可信来源 ID，读取稳定原文，保存私有原文 JSONL 和定位索引，创建一份普通持久 Codex 聊天。关闭面板不取消准备。
3. 完成后卡片显示已就绪，并在 ai-todos 内弹窗提醒，提供“进入沉淀会话 / 稍后”；不自动跳转。进入时预填“读取 task.md 开始沉淀”的提示词。用户在 Codex 中选择模型并发送；准备阶段不执行模型轮次，不写 Wiki。
4. Codex 根据 task.md 阅读原文、列出可复用经验，与用户确认，读取本地 wiki-ingest 技能及 Vault/Wiki 规范，完成 ingest 的方案、冲突讨论、批准和执行。
5. 原卡片显示沉淀聊天进度，按钮变成“继续沉淀”。再次点击复用原聊天；已有真实轮次时不重复注入或预填提示词。

ai-todos 不在新主入口承担经验提炼、模型压缩、Wiki 检索或 ingest 编排。旧候选、审核意见及原来的历史链接保持可读兼容，新卡片不进入旧审核弹窗。此前完整 ingest planner 的提案不是当前实现方式。

### 跳转耗时优化（2026-11-17）

- 首次创建聊天后直接预填并打开，不再另启 Codex CLI 查询刚创建的空轮次。
- “继续沉淀”优先使用本地持久化的开始时间或可信轮次 ID，直接打开已有聊天；服务重启后仍复用这些记录。
- 缺少本地开聊依据时仍向 Codex 核实是否有轮次；只保存“已有轮次”的确定结果。未发送的空聊天不能永久缓存为空，以免用户发送后再次预填覆盖草稿。
- 此优化去除插件侧重复初始化；首次完整读取来源和创建聊天、桌面端自身的加载耗时仍需分别观察。

### 后台准备和就绪提醒（2026-11-18）

- 新卡片入口通过 prepare_capture 启动后台准备，不等待原文读取或会话创建完成。旧 open_capture 仍保留兼容，准备中的新任务不能从此入口抢先打开。
- preparation manager 使用 SQLite meta 保存任务身份、读取/连接/创建/交接阶段、阶段耗时、失败原因与私有线程 checkpoint。快照只包含公开状态，隐藏 checkpoint 路径。
- 同源重复请求复用进行中任务；重试保存过的线程 ID，并先检查已有条目，避免重复创建或重复注入。
- 本地服务退出会取消并等待准备落盘。重启后不伪报运行或成功；中断任务可显式重试。创建请求结果不确定且没有线程 ID 时要求核对，不盲目新建。
- 就绪提醒的 unread 状态持久化。面板关闭后重新打开仍显示未处理提醒；用户选择进入或稍后才用对应 jobId 确认，过期提醒不能确认新任务。
- 多份提醒按完成时间逐份显示；编辑和旧审核弹窗显示期间先保留提醒，不覆盖当前操作。通知在 ai-todos 面板内显示，不是操作系统通知。
- 页面本地进度轮询不先等待较慢的宿主会话同步。

## 确认边界

新流程在普通 Codex 聊天里确认经验和正式写入。task.md 要求展示所有拟改文件、具体内容或 diff，等待用户明确批准；写入前检查基线，变化时重新确认；按本地 ingest 的 transport、mode、锁、原文不可变性及检查规范执行。

这是普通会话的提示词约束，不是旧网页审核票据的程序强制门禁。ai-todos 不声称能在普通 Codex 工具调用中强制拦截全部写入。是否执行、模型、工具权限和执行成本由用户的 Codex 会话管理。

## 资料和规范

- 本机 dataDir/experience-chats/<sourceId>/<sourceHash>/source.jsonl 保存所有已读取原文条目；每条保留 turnId/itemId，source-index.json 提供逐行定位。
- task.md 与 progress.json 位于对应 threadId 子目录，目录 0700、文件 0600。原文使用不可变快照，若已保存内容改变则拒绝复用。
- 来源正文和标题在提示词中明确属于不可信数据，不能执行其内嵌指令。
- task.md 包含真实 Wiki/Vault 路径和本地 wiki-ingest/SKILL.md 路径（可通过 AI_TODOS_WIKI_INGEST_SKILL 配置）。本地规范优先：raw/、wiki/chats/code/、hot/index/append-only log 及已启用 manifest。默认只沉淀到 Wiki、优先更新已有主题页；仅在用户明确需要阅读、学习或分享时额外生成人读文档，并按 Vault 规范分类。每次执行和正式写入前重新读取维护规范，历史“双份笔记”约定不作为当前要求。
- 原文快照覆盖首次准备时间前已读取的内容；再次打开不会自动改变该任务的来源范围，后续新增内容可在沉淀聊天内明确补充。

## 进度

SQLite meta 保存 source→thread 关联，服务重启后可继续复用。沉淀聊天由持久 ID 过滤，不进入普通看板，也不能再次作为沉淀来源。官方宿主同步与现有 hooks 继续记录其状态，再投影到原卡片。

细分阶段由聊天自行写入严格身份绑定的 progress.json，ai-todos 只读取状态。进度文件缺失、不合法、超大、符号链接或非普通文件时忽略；读取采用非阻塞、no-follow 和文件描述符类型检查，不允许异常文件阻塞服务。

显示状态包括待开始、运行中、待你确认、本轮结束、中断、异常、状态待同步、无可沉淀经验和“会话报告已入库”。不显示伪造百分比。Stop 或 SessionEnd 不表示已入库。最后一种状态只是聊天的明确回报，不等于插件独立核验了 Wiki 内容。新一轮开始时间持久化，旧完成回报在新轮次结束后也不会复活。

## 验证

合并前补充：来源历史保留 task_started 的真实开始点，即使新轮次在两次同步之间已经结束，也不会继续显示旧完成回报。缺失开始点、无法区分回报所属轮次时保守显示本轮结束，不猜测已入库；真实开始点可保留本轮在 Stop 前写出的完成回报。

- 完整来源/不可变快照、task.md、身份与文件类型、FIFO 不阻塞、明确进度与生命周期区分。
- 并发点击只创建一个线程、进程重启后复用、未开始时预填、有轮次后不重复预填、无 turn/start、不改原聊天、不写 Wiki。
- hooks 和宿主同步显示沉淀状态；后台聊天不新增看板卡片；新一轮使旧完成回报持续失效。
- 浏览器隔离环境：按钮直接请求 Codex deep link，源卡片出现“继续沉淀”；观察运行/等待批准阶段；原始60条完整交接，未初始化旧分析表，未启动模型轮次。
- 真实 Codex：交接42条历史原文，创建与再次打开使用同一 threadId，实际 turns/list 返回未开始并保留预填提示词。只测试元数据和跳转准备，没有向模型发送提示词、执行 ingest 或批准正式 Wiki 写入；真实桌面窗口操作不属于这轮浏览器验证。
