# 沉淀经验：模型选择与验证

日期：2026-11-16。

## 使用方式

打开“沉淀经验”，在“分析模型”和“推理强度”中选择配置，再点击“提取经验”。首次打开不再自动启动分析。模型和强度来自当前 Codex 账户的实时 `model/list`，没有写死模型名称或推理强度枚举。

服务记住上次实际启动的配置，本地浏览器和嵌入式工作台共用。运行中锁定选择器；取消任务后可换模型重新提取。更换配置会建立独立任务，不复用其他模型的分段结果。

接口依据：[Codex App Server](https://developers.openai.com/codex/app-server/) 的模型目录和线程/轮次参数；本机目录与实际返回值另行核对。

历史候选展示“提取使用”和“Wiki 对照使用”的模型与强度。已有候选的 Wiki 对照沿用原提取模型，不因后来修改选择器或偏好而切换。旧候选没有模型信息时明确显示未记录；对照使用用户当前选择，并单独记录对照模型，不补造旧提取信息。

## 调用与存储

- `src/wiki-models.ts`：模型目录分页、选择校验和实际模型响应校验。
- `src/codex.ts`：`thread/start` 显式传入 `model` 与 `config.model_reasoning_effort`；`turn/start` 传入 `model` 与 `effort`。目录查询不启动模型生成。
- `src/wiki-experience.ts`：任务保存 `modelSelection`，完成的候选继承该配置；另存 `comparisonModelSelection`。偏好保存在同一 SQLite 的 `wiki_model_preference`，与任务创建同时提交。
- 分段快照摘要包含模型配置，保证同一会话换模型后也不会混用旧断点。
- 所选模型下架、强度不支持或 Codex 返回了不同实际配置时，明确失败，不静默使用其他模型。
- 原有只读临时会话、禁用工具和人工批准写入门禁保持有效；不修改 Codex 全局配置。

兼容旧接口省略模型参数的调用；新 UI 要求先选择。服务能力版本从 `wikiUiRevision=3` 升到 `4`，旧客户端不能降级新版服务。极旧 MCP 连接仍需重新连接，原有本地工作台入口保留。
