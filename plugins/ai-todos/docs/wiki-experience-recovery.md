# Wiki 经验写入恢复

多文件写入前，ai-todos 将审核过的文件路径、写入前后内容和候选 ID 保存在本地数据库的 `wiki_experience_journal`。正常完成后，审核结果与日志删除在同一事务提交。发生可捕获的错误时，程序只尝试回滚本次确定写入的文件，并在回滚前重新检查页面；无法确认归属的内容不会自动覆盖。

如果服务提示“需要人工恢复”，说明进程可能在文件写入期间退出，或其他程序修改了涉及的页面。此时不要重复批准，也不要直接删除日志：

1. 关闭可能同时修改这些页面的编辑器和同步程序，确认没有其他 ai-todos 进程正在写入。
2. 备份 Wiki 和 `~/.ai-todos/ai-todos.sqlite`（如果配置了 `AI_TODOS_DATA_DIR`，数据库位于该目录）。备份 SQLite 前应停止 ai-todos 服务，确保 WAL 已合并。
3. 使用 SQLite 查看工具读取 `wiki_experience_journal`；`body` 中的 `files` 包含每个文件的 `path`、`before` 和 `after`，`root` 是当时的 Wiki 路径，`vaultRoot` 是人读版 Vault 路径；以 `@vault/` 开头的目标相对后者解析。内容可能敏感，仅在本机查看。
4. 对照当前页面与记录中的前后版本，人工决定每个文件应保留的内容。不得假定等于 `after` 的内容一定由本次操作写入。
5. 确认所有文件已恢复到期望状态并另行保存备份后，删除**对应 ID** 的 journal 行，再重启服务、重新提取并审核。不要批量删除其他候选或操作记录。

新候选的分析结果和用户审核意见位于 `wiki_experiences`；历史操作位于 `wiki_experience_events`。这些记录与恢复日志分开，清理 journal 不会自动标记候选为已写入。
